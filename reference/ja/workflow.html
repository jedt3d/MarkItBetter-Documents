MIB のワークフロー

公開版ガイド: v0.49.0

このページ
  • 必要な位置からソースへ入る
  • 読む状態へ戻る
  • 保存の仕組み
  • 一連の操作を試す

PREVIEW は読むための状態、EDIT は Markdown ソースを扱う状態です。直したい一文だけ編集して、すぐに読む作業へ戻れます。

必要な位置からソースへ入る

正確な修正には、PREVIEW の単語をダブルクリックします。MIB が EDIT に切り替わり、対応するソースの単語を選択します。空白のダブルクリックでは、直前の単語に近い位置へ移動します。リンクやリストなど、記号がプレビューに見えない部分で便利です。

公開版のプレビューキーには、次の違いがあります。

PREVIEW での操作 結果
テキストを選択して i 選択テキストに対応するソース位置の直後で編集
有効な選択なしで i 文書末尾で編集
a 文書末尾で編集
パレットの Switch to EDIT エディターに残っている選択・カーソル位置で再開

狙った単語を直すならダブルクリックを使います。表示結果からソースの行番号を推測する必要はありません。

読む状態へ戻る

通常の EDIT で Esc を押すと、保存先がある文書を保存し、カーソルのあるブロック付近の PREVIEW へ戻ります。

ただし Esc は、現在の操作を先に終了します。スラッシュメニューがあれば閉じ、スニペットの入力フィールドが有効ならその移動を終了し、検索欄にいる場合は検索パネルを閉じます。その操作を終えてから、もう一度 Esc で PREVIEW へ戻ります。スニペットと移動・検索も参照してください。

保存の仕組み

保存先のある文書は、入力が三秒止まったとき、EDIT から PREVIEW へ移るとき、編集ウィンドウがフォーカスを失ったときに保存されます。ファイルの移動や共有前には Command+S / Ctrl+S も使えます。

無題の内容は、保存先を選ぶまでメモリー上にあります。Save As… または保存キーでファイルダイアログを完了してください。モード変更が勝手にファイル名を決めることはありません。未保存の内容を閉じると保存・破棄・キャンセルを選べます。保存に失敗した場合は、確認できるコピーができるまで内容を残します。

一連の操作を試す

次の文書を作り、release-notes.md として保存します。

markdown
# リリースノート

読み手を中心に考える。

- [ ] サンプルを確認する
- [ ] 表現を見直す

PREVIEW に戻り、直したい単語をダブルクリックして変更し、Esc を押します。表示結果と保存内容を確かめてから、PREVIEW のタスクを切り替えてください。ソースの標準的な [ ] / [x] が書き換わります。

長時間の執筆には Focus と Typewriter の設定を調整できます。作業環境を変えても、文書は持ち運べる通常の Markdown のままです。
