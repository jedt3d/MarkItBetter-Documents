実務で使うレシピ

公開版ガイド: v0.49.0

このページ
  • 読み流せる README
  • 短い設計判断の記録
  • 証拠を残すリリース確認
  • 保守できる API ノート

通常の Markdown と公開済みの編集操作で使える出発点です。コピーして事実を置き換え、PREVIEW を確認します。Mermaid はレンダラーを含むバージョンを使っている場合に追加してください。

読み流せる README

markdown
# ノートサービス

プロジェクトノートを Markdown ファイルで保存します。

## はじめに

1. 設定例をコピーします。
2. ローカル保存先を指定します。
3. サービスを起動して health endpoint を確認します。

## コマンド

| 作業 | コマンド |
| --- | --- |
| チェック実行 | `npm test` |
| ローカル起動 | `npm run dev` |

## 参照

- [判断記録](./decisions.md)
- [Configuration](#configuration)

## Configuration

対応値と最小の例を記載します。

コマンドは架空のプロジェクトの例で、MIB の CLI ではありません。実際にあるコマンドへ置き換えます。文章を磨く前に Outline で構造を確認します。

短い設計判断の記録

markdown
# ADR: ノートを Markdown で保存する

## 背景

変更をバージョン管理でレビューし、オフラインで編集したい。

## 判断

ノートごとに通常の Markdown ファイルを使う。

## 結果

- エディターを変えても内容の変換は不要。
- ファイル移動時は相対リンクに注意する。
- 描画拡張はチームで合意する。

## レビュー

- [ ] 制約をチームと確認する
- [ ] 実装の議論へリンクする

記録が増えたら判断ごとにファイルを分け、関連記録をリンクします。図一枚にすべてを埋め込む必要はありません。Mermaid の章に今後の描画機能向けの flowchart、sequence、journey、ER の出発点があります。

証拠を残すリリース確認

markdown
# リリース確認

- [ ] バージョンと変更内容を確認する
- [ ] プロジェクトのチェックを実行する
- [ ] 失敗と未解決事項を記録する
- [ ] ユーザー向けノートを見直す
- [ ] 配布するファイルを確認する

## 検証

| チェック | 結果 | 証拠 |
| --- | --- | --- |
| Unit tests | 未実施 | 実際の報告を追加 |
| 操作確認 | 未実施 | 試したバージョンを記録 |

コマンドが存在するだけで「未実施」を「合格」に変えないでください。実行後に更新します。PREVIEW のタスクを使いながらソースを通常の GFM に保ち、必要な証拠行を表のポップアップで追加できます。

保守できる API ノート

method、path、目的を表にまとめ、endpoint ごとに見出しを付けて request、期待する response、エラー条件、バージョン前提を記載します。Link、Table、Code block、Collapsible が便利です。長い payload はコードフェンス、補足は <details> に入れます。

共有前に保存、プレビュー、相対リンクを確認し、例のコマンドを対象システムで試します。MIB はノートを整形できますが、外部サービスの契約まで検証するものではありません。
