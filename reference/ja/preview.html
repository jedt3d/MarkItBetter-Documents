プレビューとソースをつなぐ

公開版ガイド: v0.49.0

このページ
  • 表示された文章から修正する
  • 操作できるタスクリスト
  • 長い技術文書を読む
  • 読み手が受け取る結果を確認する

PREVIEW は操作できる読書画面です。リンク、検索、タスクの切替、適切なソース位置への編集移動ができます。記号を含む Markdown と表示結果が大きく違う場所で特に役立ちます。

表示された文章から修正する

変えたい単語をダブルクリックします。対応位置を求められる場合、ソースの単語が選択されます。空白や難しい対応では近い位置へ移る場合があるため、置換前に範囲を確認します。

編集後の Esc は、カーソルのある描画ブロックへ戻ります。長いコード、開いた details、画像などで表示の高さが変わるため、二つの表現で同じスクロール位置を保つより、ブロックを基準にする方が扱いやすくなります。

PREVIEW のキー入力には選択に応じた挙動があります。ワークフローで、単語のダブルクリック、選択後の i、末尾追加の a の違いを確認してください。

操作できるタスクリスト

markdown
- [ ] リリースを準備する
  - [x] サンプルを確認する
  - [ ] リンクを確認する

PREVIEW のタスク操作はソースの [ ] / [x] を更新します。親の切替は子にも反映します。一部の子だけ完了すると親は混在状態を示せますが、これは子から導かれる表示で、新しい Markdown 記号として保存されません。

Preferences → Tasks で完了項目の薄さと取り消し線を選びます。これは表示上の選択です。別の人が開くファイルは標準 GFM のタスクリストのままです。

長い技術文書を読む

見出しには Outline、語句には Find を使います。見出し・脚注リンクはプレビュー内をスクロールします。補足が気になるときは <details> を閉じ、必要な手順を読むときに開きます。

読み幅は既定で自動調整され、パネルの利用可能領域に応じて変わります。Preferences での手動幅は、そのファイルを開いている間の指定です。別ファイルを開くと自動へ戻ります。60%/90% の説明は内容幅を参照してください。

読み手が受け取る結果を確認する

リスト、脚注、表、HTML の構造を変えたら PREVIEW へ戻ります。コードの強調は grammar を必要時に読むため、本文の後から色が付くことがあります。未対応言語はプレーンコードとして読めます。

同じ文書でも他の Markdown ツールでは見え方が異なります。共有時は通常の記法を優先し、拡張を使うなら明示します。今後の Mermaid ビューアーが加える Source、Find、拡大操作は、v0.49.0 の通常のコードフェンスにはありません。
