# รูปแบบ Markdown ที่รองรับ

รุ่นเผยแพร่รองรับ CommonMark ร่วมกับ GFM และส่วนขยายที่ระบุไว้โดยตรง ความรู้ Markdown เดิมนำมาใช้ได้มาก แต่รูปแบบที่โปรแกรมอื่นรองรับไม่ได้กลายเป็นความสามารถของ MIB โดยอัตโนมัติ

## ต้นฉบับที่ใช้บ่อย

```markdown
## การตั้งค่า

ใช้ **ตัวหนา**, *ตัวเอียง*, `inline code` และ ~~ข้อความที่เลิกใช้~~

> เก็บเหตุผลไว้ใกล้การตัดสินใจ

1. เปิดบันทึก
2. แก้ไขข้อมูล

- [ ] ตรวจตัวอย่าง
- [x] บันทึกเอกสาร
```

หัวข้อ รายการ blockquote ลิงก์ รูปภาพ โค้ดแบบ fence หรือเยื้อง และเส้นคั่นใช้ Markdown ตามปกติ GFM เพิ่มตาราง pipe ขีดฆ่า task list และ autolink [งานในรายการ](preview.html#interactive-task-lists) ยังสลับสถานะจาก PREVIEW ได้

## ลิงก์ รูปภาพ และจุดอ้างอิง

```markdown
[แหล่งอ้างอิง](https://example.com)
[อีกบันทึกหนึ่ง](./decisions.md)
[หัวข้อ Configuration](#configuration)
![ข้อความอธิบายภาพ](./images/architecture.svg)
```

บันทึกเอกสารก่อนใช้อ้างอิงแบบสัมพัทธ์ เก็บรูปในโฟลเดอร์เดียวกันหรือโฟลเดอร์ย่อย การเข้าถึงรูปในเครื่องมีขอบเขต พาธที่ไต่ออกนอกโฟลเดอร์อาจไม่แสดง หากเพิ่ง Save As แล้วรูปยังไม่ทำงาน ให้ลองเปิดเอกสารนั้นใหม่

Slug ของหัวข้อคงตัวอักษรไทยและญี่ปุ่น เปลี่ยนตัวพิมพ์เป็นเล็กเมื่อเหมาะสม ตัดเครื่องหมายวรรคตอน และแทนช่องว่างด้วยขีดกลาง ควรตั้งชื่อหัวข้อให้ต่างกันเพื่อลิงก์ได้ง่าย HTTP/HTTPS เปิดในเบราว์เซอร์ ส่วนลิงก์ Markdown แบบสัมพัทธ์เปิดในโปรแกรม

## ส่วนขยายเล็ก ๆ ของ MIB

| ต้นฉบับ | ความหมาย |
| --- | --- |
| `H~2~O` | ตัวห้อย |
| `x^2^` | ตัวยก |
| `[[Ctrl + S]]` | ปุ่มคีย์บอร์ดจำลองใน PREVIEW |
| `:smile:` | ชื่อย่ออีโมจิที่รู้จัก |
| `[^note]` และ `[^note]: text` | อ้างอิงและนิยามเชิงอรรถ |

Keyboard chip แสดงข้อความตรงตัวโดยไม่มี Markdown ซ้อน ข้อความที่ไม่ปิดหรือไม่มีเนื้อหาจะยังเป็นข้อความธรรมดา เชิงอรรถใช้นิยามอีกตำแหน่งในเอกสาร ไม่ใช้รูปแบบ `^[text]` ตัวแก้ไขอาจแสดงส่วนขยายบางอย่างเป็นข้อความธรรมดา แม้ PREVIEW จัดรูปแบบให้

## โค้ดและ HTML

ชื่อภาษาหลัง fence เลือกการไฮไลต์ไวยากรณ์ ใช้ชื่อย่อที่พบบ่อย เช่น `js`, `ts`, `py` และ `sh` ได้ หากไม่มี grammar ที่รองรับ จะยังอ่านโค้ดแบบธรรมดาได้ เปลี่ยนชุดสีที่ [Preferences → Code](preferences.html#code)

`<details>` กับ `<summary>` ใช้ทำเนื้อหาพับเก็บได้ HTML จะถูกกรอง โดยตัด script และตัวจัดการเหตุการณ์ รวมถึงจำกัดเนื้อหาที่ทำงานเอง จึงไม่ควรคาดหวังว่า JavaScript, iframe หรือ widget ที่คัดลอกจากเว็บจะทำงานในเอกสาร

รองรับ inline SVG ภายใต้ข้อจำกัดการกรองของรุ่นเผยแพร่ SVG ที่มี script, `foreignObject`, การอ้างอิงภายนอก และรูปแบบที่ใช้ `<use>` บางชนิดจะไม่คงอยู่ครบ การ export เป็นเวกเตอร์แบบ passive ที่แผ่โครงสร้างแล้วแชร์ต่อได้ง่ายกว่า

## ตรวจความเข้ากันได้ก่อนส่งต่อ

Mermaid เป็น **ฟีเจอร์ที่จะตามมา** ใน v0.49.0 fence ของมันจะแสดงเป็นโค้ด ส่วนสูตรคณิตศาสตร์ wiki-link และ callout/admonition ยังไม่อยู่ในรูปแบบของรุ่นเผยแพร่ที่คู่มือนี้อธิบาย อย่าใช้ผลลัพธ์ของเว็บไซต์คู่มือนี้เป็นหลักฐานว่าแอปรุ่นที่ติดตั้งรองรับส่วนขยายเดียวกัน

เริ่มจาก Markdown ปกติ ตรวจ PREVIEW และลองเปิดไฟล์ตัวแทนในเครื่องมืออื่นที่ทีมใช้อยู่ เก็บต้นฉบับไว้เมื่อทดลอง renderer หรือส่วนขยายใหม่
